# 风险政策：一次立法、终身执行

## R — 原文 (Reading)

> "每次面对风险选择，倾向于窄框架的决策者都会构建偏好。他们如果掌握了风险政策，在相关问题出现时就会做出更明智的决策。风险政策的常见例子是'购买保险时，总是尽可能选择最高的免赔额''永远不要购买延保'。风险政策是一个宽框架。"
>
> — 丹尼尔·卡尼曼，第31章

---

## I — 方法论骨架 (Interpretation)

重复出现的风险决策，每次重开"情绪评估"既是负担也是失血源：单次的损失厌恶会把正期望的长期策略拦在门外，也会让人为微小风险反复支付不成比例的保费。风险政策把决策成本从"情绪评估"降为"规则检索"：

1. **立法**：对每一类重复风险决策，一次性定一条原则（写下来）。书中例子：保险永远选最高免赔额、永远不买延保、报价低于成本的单不接。
2. **执行**：决策出现时只做规则检索，不再重开偏好构建；偶尔的亏损因"政策长期有利"而不再刺痛——"虽然偶尔的损失会带来痛苦，但想到你的政策从长远来看会有利于财富增长，你的痛苦就会减少或消除"。
3. **修法不破例**：政策失效时走年度复盘修改政策本身，而不是当场破例——破例一次，政策就退化成每次重建偏好。
4. **动机层**：用"这类情况我一年遇到多少次"把单次偏差换算成年度成本，给立规提供理由。

组织版：塞勒观察到的 CEO——要求 25 位主管全部接受合理风险，用组织的宽框架消除层层叠加的过度谨慎；"外部视角+风险政策"应成为组织目标。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 塞勒的 CEO 与 25 位主管
- **问题**: 每位主管各自面对"等概率亏一大笔或赚双倍"的决策，全部拒绝——公司整体因此放弃了所有合理风险。
- **方法论的使用**: CEO 宣布"我希望所有高管都接受风险"——他自然地采用了涵盖 25 个赌注的宽框架，把每位主管的单次恐惧聚合成长期组合。
- **结论**: 组织层面用政策（而非临场说服）矫正单次损失厌恶。
- **结果**: 作者将"外部视角+风险政策"列为组织的双药方。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 反复买保险/延保/保修，每次都纠结一遍。
2. 自由职业者/小老板反复决定"这单接不接、报多少"。
3. 投资/定投纪律屡屡被单次波动破坏。
4. 团队同类审批（折扣权限、退款、和诉）每次都重新吵。

### 语言信号 (用户的话里出现这些就应激活)

- "每次都纠结""帮我定个原则/规矩""以后就按……办"
- "又是这个问题""上次的教训呢"
- 英文：standing rule / risk policy / precommit / default decision rule

### 与相邻 skill 的区分

- 与 `wide-frame-trader` 的区别：宽框架是**每次临场重述**"这是序列之一"；风险政策是**一次立法**，适合频率高到不值得每次重述的场景。政策本身就是固化下来的宽框架。
- 与 `fourfold-risk-locator` 的区别：定位器处理单个决策；政策把整类决策一次性处理掉。

## E — 可执行步骤 (Execution)

1. **盘点重复决策**：列出会反复出现的同类风险决策及其年频率。
   - 完成标准：清单+每类年次数
2. **逐类立法**：为每类写一条可机械执行的原则（含明确触发条件与例外门槛=断腿级）。
   - 完成标准：原则书面化，一人一句能复述
3. **机械执行**：决策出现时只检索规则；记录"按政策执行"。
   - 判停条件：出现"罕见且决定性"的新信息 → 触发**修法流程**（年度复盘），不当场破例
4. **年度复盘**：用过去一年的统计检验政策是否仍有利；环境变了就修法。
5. **换算动机**：向自己/团队展示"单次偏差×年频率=年度成本"，巩固立法理由。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 一次性决策——没有重复就没有政策，硬立规是伪纪律。
- 环境已剧变仍机械执行旧政策——复盘义务优先于执行纪律。
- 涉及道德/法律红线的决策——不可用"政策"规避判断责任。

### 作者在书中警告的失败模式

- 不立规的代价：每次重建偏好=每次被单次损失厌恶劫持；重复小险过度投保是长期复利失血（ce47/ce50）。
- 破例的传染性：为一次"特殊情况"破例，政策即名存实亡。

### 作者的盲点 / 时代局限

- 政策质量取决于立法时的统计是否可靠；书中未处理"错误政策被长期机械执行"的矫正机制——年度复盘步骤是本 skill 自加的工程化补丁，需注明。

### 容易混淆的邻近方法论

- 习惯养成：习惯靠重复自动化，政策靠书面规则+复盘治理；政策可以被论证修改，习惯不能。
