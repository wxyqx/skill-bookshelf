# 事前验尸（premortem）

## R — 原文 (Reading)

> "在组织即将做出某个重要决定，但还未正式敲定时，克莱因建议召集了解该决定的人开个小会。会议的开场白是：'想象一下，我们穿越到一年后，实施了目前的计划，结果一败涂地。请用5～10分钟的时间写下那场灾难的简史。'"
>
> — 丹尼尔·卡尼曼，第24章

---

## I — 方法论骨架 (Interpretation)

计划讨论会最大的敌人不是没人发现问题，而是**质疑不合法**：领导表态后，公开质疑会被解读为不忠诚，有识之士的想象力无处安放。事前验尸把"事后聪明"这一最顽固的偏差反转为工具：

1. **时机**：决定尚未敲定——敲定后效果骤减。
2. **宣布灾难剧本**：不说"谁觉得有风险"（没人想当扫兴者），而是宣布"一年后计划已惨败，写灾难简史"——每个人都成了"事后解释者"，而事后解释是系统1最擅长的事。
3. **独立书写**：各自写，不先讨论（防锚定在率先发言者）。
4. **归并清单**：轮流陈述、合并同类项，按可能性×杀伤力排序。
5. **回流决策**：为高优先风险补预防措施或触发器，修改计划后再定。

个人版是"饮水机预演"：决策前预演"我最挑剔、见多识广的同事会怎么挑这份方案的毛病"——旁观者认知负担轻，能绕开行动者的自我辩护。

## A1 — 书中的应用 (Past Application)

### 案例 1: 达沃斯的 CEO
- **问题**: 如何让大型组织在过度乐观中保住质疑通道。
- **方法论的使用**: 作者在达沃斯随意描述克莱因的事前验尸，身后有跨国公司 CEO 喃喃自语："就凭这个好点子，来达沃斯开会值了！"
- **结论**: 该程序以极低成本激活了组织内的反对视角。
- **结果**: 作者将其列为组织"驯服乐观"的最妙方法，并纳入结论章的组织纠偏四件套。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 方案评审会一片赞成，即将拍板。
2. 自己写的计划想在上报/发布前找漏洞。
3. 团队曾反复在同类项目上翻车，想装一个事前防线。
4. 用户直接要求"帮我预演一下失败"。

### 语言信号 (用户的话里出现这些就应激活)

- "这个计划行不行""帮我挑挑毛病""上线/提交前再检查一下"
- "大家都觉得没问题（所以我想找茬）"
- 英文：premortem / what could go wrong / devil's advocate / review my plan

### 与相邻 skill 的区分

- 与 `bias-proof-review` 的区别：方向相反——本 skill 在事前**利用**后见之明的想象力；后者在事后**抑制**后见之明的改写。一个方案建议两个都用：事前验尸 + 事后复盘纪律。
- 与 `high-stakes-slow-thinking` 的区别：总闸识别"需要慢下来"，premortem 是集体决策雷区的专用工具。

## E — 可执行步骤 (Execution)

1. **时机检查**：决定敲定了吗？
   - 判停条件：已敲定且已投入 → 改用事后复盘（bias-proof-review），不假装事前
2. **宣布剧本**：主持者宣布"一年后计划已惨败"的开场白。
   - 完成标准：所有与会者理解是找死因，不是表态支持
3. **独立书写**：5–10 分钟各自写下灾难简史，期间不讨论。
   - 完成标准：每人至少 2–3 条具体死因（含"为什么在当时看不出来"）
4. **归并排序**：轮流陈述、合并同类项，按可能性×杀伤力排序。
   - 完成标准：一张去重的风险清单
5. **回流决策**：对前 3 项风险补预防措施/监控触发器/修改计划；之后才允许敲定。
   - 判停条件：风险清单全部有对策 → 推进；存在无对策的高杀伤项 → 回到方案设计

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 决策已定、人心已定——此时开会只会产生"走过场的风险清单"。
- 与会者毫无相关信息的纯仪式场合。

### 作者在书中警告的失败模式

- 集体思维：领导先表态再开会，质疑仍会被忠诚信号压制——主持者必须最后表态（ce44）。
- 作者明言 premortem **不是万灵丹**：它只能部分抵消 WYSIATI 与不加批判的乐观，不能替代参考类别统计（外部视角）。

### 作者的盲点 / 时代局限

- 书中未处理 premortem 可能诱发的过度悲观与决策瘫痪；执行时应限定风险清单规模与处理时限。

### 容易混淆的邻近方法论

- 通用"头脑风暴风险"：区别在剧本设定（"已失败"的事后叙述比"可能的风险"枚举更容易逼出具体细节）与独立性（先写后议）。
