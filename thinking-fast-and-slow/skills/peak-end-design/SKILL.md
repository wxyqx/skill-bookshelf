# 峰终设计：先声明在为哪个自我优化

## R — 原文 (Reading)

> "如果目标是减少患者的疼痛记忆，那么降低疼痛的峰值可能比缩短检查时间更重要。……如果目标是给患者留下较好的回忆，那么逐渐缓解疼痛可能比突然终止疼痛要好。"
>
> — 丹尼尔·卡尼曼，第35章

---

## I — 方法论骨架 (Interpretation)

回顾性评价由**峰值与结尾的平均值**决定，时长几乎被完全忽视（时长忽视）。这意味着两件反直觉的事：

1. **加时间可以改善记忆**：一段多 30 秒温和期的长检查，回忆比短而剧痛的更好（冷手实验：80% 的人自愿重复更长的版本，只因它的"记忆"更好）。
2. **缩短可以伤害口碑**：把 8 分钟的剧痛换成 20 分钟渐轻的流程，体验总量更大、记忆更好——为哪个自我优化，决定了正确答案完全相反。

所以程序的第一步不是设计，而是**声明目标**：为体验自我（减少实际痛苦总量）→ 快速完成、哪怕峰值更高；为记忆自我（口碑、回头客、值得讲述）→ 压低峰值、安排渐好的结尾。结尾是杠杆最大的位置——"结局往往决定了故事的特色"。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 结肠镜实验
- **问题**: 患者对结肠镜的整体痛苦由什么决定？
- **方法论的使用**: 154 名患者每 60 秒自报疼痛：回顾评分被"峰值与结尾的均值"准确预测，检查时长（4–69 分钟）对评分无影响；随机让一半患者结尾多延 3 分钟缓和期，他们对复查的接受率显著更高。
- **结论**: 记忆不录像，它剪片子。
- **结果**: 直接医疗含义：降峰值/渐好结尾 vs 快速完成，取决于你要减少痛苦还是减少恐惧复查的人。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计医疗/检查/办事流程，希望用户"下次还来"。
2. 客服投诉处理：结尾决定这场危机被讲成什么故事。
3. 活动议程、课程、产品开箱的收尾环节。
4. 纠结"流程能不能再压缩"时，评估记忆代价。

### 语言信号 (用户的话里出现这些就应激活)

- "体验怎么设计""结尾怎么安排""客户带着坏印象走了"

### 与相邻 skill 的区分

- 与 `two-selves-check` 的区别：two-selves 管个人**决策**（这次选择在为谁买单）；本 skill 管**设计**（为别人或流程安排体验结构）。先懂两个自我，再动手设计。
- 与 `bias-proof-review` 的区别：复盘管评估过去决策；本 skill 利用记忆规则**向前设计**。

## E — 可执行步骤 (Execution)

1. **声明目标**：为体验自我还是记忆自我优化？写明并确认。
   - 完成标准：目标落在两者之一（或显式的双目标权重）
   - 判停条件：用户只要最短时间 → 纯效率方案，不套峰终
2. **识别峰值**：这段体验中感受最强烈的时刻在哪（通常是痛苦最高点或惊喜最高点）？
   - 完成标准：峰值时刻已定位
3. **按目标设计**：记忆自我 → 压低峰值 + 制造渐好的结尾；体验自我 → 压缩时长、允许峰值换效率。
   - 完成标准：结尾环节有明确设计（收尾动作、告别语、小赠品、总结）
4. **时长复核**：检查被砍掉/延长的部分是否承载了"渐好结尾"的功能——砍结尾等于砸口碑。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 该记忆无价值或需要"被遗忘"的场景（原文也讨论了"想要失去记忆"的打针谜题——有人愿意为更差记忆付费）。
- 把峰终当作操纵话术：掩盖实质问题、只修饰结尾的服务设计会反噬（书中的规范立场是测量与诚实呈现，不是包装）。

### 作者在书中警告的失败模式

- 时长忽视有循环论证嫌疑：作者用"结尾时状态变了"化解一切时长反例——峰终定律的适用域是**回顾性整体评价**，不要拿它预测过程中每一刻的感受（ce60 的适用域标注）。
- "我会永远记住"是可能出错的预测而非事实。

### 作者的盲点 / 时代局限

- 峰终实验多为短期、单次体验（结肠镜、冷手、假期）；跨月、跨年的长期记忆研究证据较薄；书中的规范性争论（"该按体验总量还是叙事评价人生"）作者自认没有答案——设计商业体验可用，用于裁决他人人生时只提供双测量并陈。

### 容易混淆的邻近方法论

- 通用"服务蓝图"：流程设计工具很多；本 skill 的独特点是**先声明为哪个自我优化**，否则两个相反的设计（缩短 vs 延长渐好段）都会显得"正确"。
