# 钓鱼思维 (Bait-the-Fish Thinking)

## R — 原文 (Reading)

> "每一年夏天我都去梅恩钓鱼。我喜欢吃杨梅和奶油，可是水里的鱼爱吃小虫。所以我去钓鱼的时候，不想我所要的，而想牠们所需要的。世界上唯一能影响对方的方法，就是谈论他所要的，而且还告诉他，如何才能得到它。"
>
> — 戴尔·卡耐基, 第一篇·第三章

---

## I — 方法论骨架 (Interpretation)

钓鱼思维是一个说服起点转换器——从"我要什么"切换到"对方想要什么"。它不是技巧而是认知框架：你的需求不重要，对方的需求才是一切说服的起点。方法：(1) 识别对方当前最强烈的需求或恐惧，(2) 把你的请求重新包装成满足对方需求的路径，(3) 用对方语言而非你的语言表达。这个框架的反直觉之处在于：大多数人说服失败，不是因为他们说得不够多，而是因为他们从头到尾都在说"我要什么"——这相当于用杨梅去钓鱼，而鱼只吃虫。

## A1 — 书中的应用 (Past Application)

### 案例 1: 钓鱼比喻——用虫不用奶油
- **问题**: 卡耐基喜欢吃杨梅和奶油，但鱼不爱吃这些。如何钓到鱼？
- **方法论的使用**: 不想自己所要的（杨梅和奶油），而想鱼所需要的（小虫）。用虫做饵，而非用自己偏好的食物。
- **结论**: 说服不是给对方你想给的，而是给对方想吃的。你喜欢的理由对对方毫无吸引力。
- **结果**: 这一比喻成为全书说服术的核心隐喻——影响他人的唯一方法是谈论对方所要的。

### 案例 2: 教育孩子别吸烟——从棒球队需求出发
- **问题**: 如何让孩子不吸烟？直接教训"别吸烟，吸烟有害健康"通常无效。
- **方法论的使用**: 不从"吸烟有害"（父母关心的）出发，而从孩子想参加棒球队的需求出发——"吸烟会让你不能参加棒球队"。
- **结论**: 孩子不关心健康风险（那是父母的恐惧），但关心自己能不能打棒球（那是他的需求）。把你的请求连接到他的需求上。
- **结果**: 孩子因为害怕失去打棒球的机会而远离吸烟——这比任何健康说教都有效。

### 案例 3: 罗斯福见客前准备对方感兴趣的话题
- **问题**: 如何让每一位来访的客人都感到被重视和尊重？
- **方法论的使用**: 罗斯福在接见每位客人前，都会提前了解对方感兴趣的话题，然后从那个话题开始交谈。
- **结论**: 让对方感到被重视的方式，不是展示你的博学，而是谈论对方在乎的事。这是钓鱼思维在社交关系中的应用。
- **结果**: 客人离开后都觉得罗斯福是最有趣的人——实际上他大部分时间在听对方谈自己感兴趣的事。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 说服老板、同事或客户接受一个方案，但对方不感兴趣或抗拒，不知道从什么角度切入。
2. 想让孩子或家人改变行为，但直接说教反复无效。
3. 设计营销文案或销售话术，不确定该从什么角度打动目标受众。
4. 谈判中僵持，双方各说各的理，找不到突破口。
5. 程序员想说服老板采用新技术栈，但老板只关心成本——需要把技术优势翻译成成本语言。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么说服他？" / "怎么让对方同意" / "how to persuade"
- "他不理解我" / "他为什么不同意"
- "对方想要什么" / "what does he want"
- "站在对方角度" / "钓鱼思维" / "bait the fish"
- "我说了好多遍但他就是不听"
- "他不感兴趣" / "他不在乎这个"

### 与相邻 skill 的区分

- 与 `listening-as-persuasion` 的区别: 钓鱼思维是分析对方需求后主动设计"饵"（内容设计）；倾听引导法是让对方在表达中自己暴露需求（信息收集）。两者可组合——先倾听发现需求，再用钓鱼思维设计满足路径。
- 与 `reputation-anchoring` 的区别: 钓鱼思维找到对方现有需求并满足它（回应已有需求）；声誉锚定是赋予一个新身份让对方主动靠拢（创造新的自我认同）。前者是"给他想吃的"，后者是"让他想成为那样的人"。
- 与 `yes-ladder-socratic` 的区别: 钓鱼思维关注"说什么内容能打动对方"（内容层面）；yes-ladder 关注"以什么节奏推进对话"（结构层面）。两者可组合——用钓鱼思维确定说什么，用 yes-ladder 确定怎么说。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **需求识别**
   - 问自己: "这个人现在最想要什么？最怕什么？"
   - 关键动作: 区分"他应该想要的"（你的假设）和"他实际想要的"（他的行为证据）。如果不确定，先用 `listening-as-persuasion` 收集信息。
   - 完成标准: 用一句话写出对方的核心需求（如"他最关心成本控制"或"她最怕在领导面前丢面子"）。

2. **连接设计**
   - 问: "我的请求如何满足他的需求/消除他的恐惧？"
   - 关键动作: 找到你的请求和对方需求之间的因果连接。如果找不到直接连接，寻找间接连接（如"满足你的需求需要先做X，而X正是我的请求"）。
   - 完成标准: 一句话说明你的请求和他的需求之间的连接。
   - 判停条件: 如果找不到任何真实连接，说明你的请求可能确实不符合对方利益——此时不应强行说服，而应重新评估请求本身。

3. **语言转换**
   - 用对方的语言而非你的语言表达请求。
   - 关键动作: 把你的专业术语、你的视角词汇替换为对方的日常语言。如"采用微服务架构"→"让系统不再一崩全崩"。
   - 完成标准: 表达中不包含你的专业术语或你的视角词汇，全部使用对方会自然使用的词汇。
   - 判停条件: 如果你的表达中仍包含专业术语或你的视角词汇→重写，直到用对方能直接理解的语言。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **对方需求已明确表达且与你的目标直接一致时**: 如果对方已经想要你提供的东西，直接说即可，不需要转换视角。
- **需要展示客观事实而非说服时**: 如法律证词、科学报告、安全通报——这些场景需要事实陈述而非需求迎合。
- **对方处于情绪崩溃状态时**: 此时对方无法理性处理任何信息，应先用 `listening-as-persuasion` 让情绪释放。

### 作者在书中警告的失败模式

- **把"猜对方需求"变成"假设对方和自己一样"**: 这是投射不是同理心。钓鱼思维要求基于对方的行为证据推断需求，而非把自己的需求套到对方身上。
- **只谈对方需求而不连接自己的请求**: 了解了对方需求后，如果不能把你的请求连接到对方需求上，就只是讨好而非说服。

### 作者的盲点 / 时代局限

- 1936 年的案例基于相对简单的商业和社交场景；现代复杂组织中，对方需求可能是多层的、矛盾的（如老板既想降成本又想要最好的效果），需要更深层的需求分析。
- 未讨论"对方需求本身不合理或有害"的情况——如果对方想要的东西不道德或违法，满足它不是说服而是纵容。

### 容易混淆的邻近方法论

- **与"同理心转换公式"的区别**: 钓鱼思维是找对方"想要什么"（需求层面）；同理心是理解对方"为什么这样做"（动机层面）。同理心是钓鱼思维的前置条件——理解了对方为什么这样做，才能更准确判断他想要什么。在本书中，同理心转换公式作为钓鱼思维的子组件保留。
- **与"投其所好/拍马屁"的区别**: 钓鱼思维是找到真实需求并设计满足路径（功能性）；拍马屁是迎合表面喜好以讨好（情绪性）。前者改变行为结果，后者只改变印象。
