## 逐条结果

### ✅ should-trigger-01
- **Prompt**: "项目明天就要上线了，但我总觉得哪里不对劲，又说不上来。这几天一直在赶进度，感觉脑子都转不动了"
- **判断**: 应该触发
- **理由**: "赶进度""脑子转不动"是典型的时间稀缺+带宽负担信号，且涉及重要决策（上线），符合管窥决策校验的触发条件
- **预期匹配**: ✅ 匹配

### ✅ should-trigger-02
- **Prompt**: "回头看上次的决定，觉得自己当时怎么那么蠢，明明那么明显的问题居然没看到"
- **判断**: 应该触发
- **理由**: "当时怎么没看到"是管窥的典型后知后觉表述，用户在回顾决策失误，需要管窥理论的解释和预防建议
- **预期匹配**: ✅ 匹配

### ✅ should-trigger-03
- **Prompt**: "月底了钱不够花，我得决定先不付哪笔账单。这个月开销太大了"
- **判断**: 应该触发
- **理由**: 金钱稀缺下的财务决策，用户处于管窥状态，可能会忽略某些账单延期的长期代价
- **预期匹配**: ✅ 匹配

### ✅ should-not-trigger-01
- **Prompt**: "帮我算一下这个投资的年化收益率是多少"
- **判断**: 不应触发
- **理由**: 纯计算问题，不涉及稀缺状态下的决策盲区
- **预期匹配**: ✅ 匹配

### ⚠️ should-not-trigger-02 (跨skill混淆)
- **Prompt**: "我感觉最近脑子不够用，总是忘事，效率特别低"
- **判断**: 容易误触发
- **理由**: "脑子不够用"既可能指向带宽管理（总量问题），也可能让用户联想到"视野狭窄/管窥"。description 中需要更明确地区分：管窥是"注意力方向窄化"，带宽是"整体容量不足"
- **预期匹配**: ⚠️ 部分匹配（可能会误触发，需要优化 trigger 描述）

### ✅ should-not-trigger-03 (跨skill混淆)
- **Prompt**: "想借点钱周转一下，下个月发工资就还"
- **判断**: 不应触发（应触发借用警觉清单）
- **理由**: 用户明确提到"借钱"，这是借用警觉清单的强触发词。管窥校验是通用工具，在有更具体的借用场景时，应让位给更专门的 skill
- **预期匹配**: ✅ 匹配

### ✅ edge-01
- **Prompt**: "我在考虑要不要换工作，列了很多 pros and cons"
- **判断**: 边界——需要更多信息
- **理由**: 换工作本身是重大决策，但不一定处于稀缺状态。如果用户是被裁压力下急着找工作，则触发；如果是从容考虑更好的机会，则不触发。skill 应先询问"你现在是有时间压力吗？"
- **预期匹配**: ✅ 匹配（边界处理合理）

## 失败分析与改进

### 问题：should-not-trigger-02 可能误触发
- **原因**: "脑子不够用"与管窥和带宽都相关，区分度不够
- **改进方案**: 在 description 中更强调"决策时忽略了什么""当时怎么没想到"等管窥特有的表述，与"整体状态差/效率低"的带宽场景区分开

## 改进后的 description 微调建议

当前描述已经比较准确，但可以在触发信号中加强"决策盲区"和"忽略"的关键词，
减少与 bandwidth-management 的混淆。
